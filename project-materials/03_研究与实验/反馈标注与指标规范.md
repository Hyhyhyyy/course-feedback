# 反馈标注与指标规范

当前状态：按用户本轮要求将首页更新为六类并列；以下子类与边界为待试标、待讨论的设计建议。此为项目自建规范，不是现成政府量表。先定义教师任务，再选技术，不受已有音视频项目实现限制。

## 1. 六类首页及细分

| 首页类别 | 子类与显示规则 | 教师要回答的问题 | 主要依据 |
|---|---|---|---|
| 问题与求助 | 具体/隐含问题、核验提问、方法拓展、笼统求助、待核疑问 | 反馈者提出了什么信息需求？ | E11、E22、E25；保留规则为项目扩展 |
| 知识交流 | 回答解释、推理比较、概念标记、归纳总结、相关经验、知识补充、纠错主张 | 反馈者提供了什么知识内容？ | E11、E22 |
| 理解状态自述 | 自述理解、部分理解/不确定、未理解/跟不上 | 反馈者如何描述自己的理解？ | E43；自发弹幕编码为项目适配 |
| 学习情绪 | 愉悦/兴趣、希望/信心、惊讶、困惑感、焦虑、挫败、无聊、混合/待核 | 表达了何种学习相关感受？ | E02教育理论；E40多标签方法 |
| 教学评价 | 内容/讲解/例题/节奏/音画/资料：肯定、批评、混合、待核 | 哪些具体处理受到肯定或批评？ | E39、E41 |
| 改进建议 | 增补解释/条件、例题练习、节奏结构、音画资料 | 希望教师改变什么？ | E23、E39 |

六类是多轴检索入口，不相加评分。教学评价的肯定/批评/混合、理解自述的理解/部分/未理解、情绪的积极/消极/混合与未知分别显示，正面信息保持可见。情绪子类是教育理论适配，不等于SemEval原始标签，未冻结前不计算细情绪强度。

## 2. 每条记录同时回答四个问题

- 表达了什么：六类标签与子类，允许多个；原文中标出各标签对应的证据短语。
- 针对什么：知识点/步骤、例题、组织节奏、板书字幕、声音画面、教师整体、反馈者自身或对象不明。
- 指向哪里：弹幕播放位置与其所指讲解区间分开记录；音视频辅助提出区间候选，允许滞后和多候选。
- 凭什么判断：弹幕证据短语、相关转录/画面/音频引用、归属依据与待核原因。表达类别证据与原因解释证据不混淆。

情绪与评价倾向分别记录。“我好焦虑”可能有负面情绪，但没有教学批评；“终于懂了”属于理解自述，不能自动推导愉悦。惊讶、困惑感等不能只凭类别名固定为正面或负面；根据原文另标倾向或不明确。

## 3. 边界例子（均为合成）

| 原文 | 建议标签 | 判定理由 |
|---|---|---|
| 这段懂了 | 理解状态自述：自述理解 | 没有情绪或具体教学评价，不自动标愉悦/肯定 |
| 终于顺过来了，好开心 | 理解状态自述＋学习情绪：愉悦 | 状态与感受有独立文本依据 |
| 这个反例真清楚 | 教学评价：例题/讲解肯定 | 肯定具体对象，但未直接自述学会 |
| 老师太强了 | 教学评价：整体肯定 | 不自动归属某种具体教学技巧 |
| 为什么能约掉x | 问题与求助：步骤询问 | 无问号也保留；不自动当困惑情绪 |
| 这步没懂，为什么能约掉x | 理解状态自述＋问题与求助 | 理解困难与具体信息需求同时存在 |
| 我基础差，这里没跟上 | 理解状态自述：未理解；对象自身/前置知识 | 不自动归责教师，不虚构具体问题 |
| 太快了，没跟上，请慢一点 | 教学评价：节奏批评＋理解自述＋改进建议 | 三种表达分别标注，缺哪种证据不补哪种 |
| 不懂，求再讲一遍 | 理解状态自述＋问题与求助；改进建议候选 | 笼统理解求助保留；明确重讲请求可另标教学改动 |
| 崩溃了 | 学习情绪：挫败/待核 | 若无信息需求，仅情绪仍保留，不编造问题 |
| 因为x非零，所以这一步可以约 | 知识交流：解释 | 数学正确性另核，不等于已测掌握 |
| 这步是不是少了负号 | 问题与求助＋知识交流：纠错主张 | 核验疑问与知识主张并存，须回看原画面 |
| 请补一道反例 | 改进建议 | 请求不自动表示不满，不一定是知识提问 |
| 不如用另一种方法，这种也能算 | 知识交流：方法比较；改进建议待核 | 只有确实请求改变教学时才标建议 |
| 懂了懂了（并没有） | 理解状态自述：否定/待核 | 保留否定，不能只抓“懂了” |
| 打卡 | 学习行为记录（辅助） | 不推导积极情绪、理解或参与深度 |

同条可多标签；同类别按comment_id去重。单纯提问不默认标知识交流；自述未理解不自动标情绪。明确的困惑感可标情绪，理论上情绪与认知可关联，但不能抹去文本证据差异。无关/社交、行为记录和未知另留辅助去向。

## 4. 指标和分母

概念与验证依据见《研究依据与设计论证》和《权威依据与功能映射》E21、E27、G节。六类首页只是不同功能视图；各轴指标独立报告，不计算一个总质量分，也不以六类标签的内部一致性证明量表效度。

N_raw：已取得的原始记录数，不声称平台历史全集。N_valid：通过格式/范围校验且不是重复传输记录的条数。N_teach：其中教学相关弹幕数。自然出现的相同文本默认保留；另展示近重复敏感性分析，不能把两个同文评论默认视为同一个人。

- 弹幕密度 = 时间窗内 N_valid / 该窗实际分钟数。末窗按实际时长计算。原始全集未知、分片缺失在图上标明。
- 某类表达占比 = 窗内具有该标签的不同弹幕数 / 窗内 N_teach；同步列出分子、分母和未知数量。多标签之和可超过 100%，不画成互斥饼图。没有标签不意味着另一标签。
- 知识点支持条数 = 明确归属该知识点的不同弹幕数；多候选单列，不重复塞进每个知识点。跨点总计去重后重算。
- 高频问题支持度 = 该问题簇不同弹幕数；展示原始支持与近重复合并后支持两种统计结果。它不等于人数或独立证据数量。
- 归属覆盖 = 明确归属条数 / 待归属的教学相关条数；报告拒判部分。不能通过只处理容易弹幕抬高准确率。
- 词/短语频次 = 提及该短语的不同弹幕数；保留“不懂”“没看清”等整体短语，公开停用词、同义合并表及处理版本。词云面积只是频次提示，附可排序频数列表与原文证据。

- 问题弹幕数：含至少一个已确认问题或笼统求助的不同comment_id数；待核单列。
- 问题单元数：可辨识信息需求的question_unit_id数；同一弹幕多问可产生多个单元。问题簇数：同义信息需求归并后的簇数。三种数不能互相替代。
- 问题单元识别召回率：独立人工参照中的问题单元被正确识别的数量/参照单元总数；事先冻结片段和语义匹配规则。一条弹幕只找到两问中的一问不能算两个都对。
- 已识别问题保留完整率：完整报告清单中仍可追溯的不同问题单元数/输入聚合阶段的不同问题单元数；集合核验能检查工程丢失，不能证明模型发现了全部问题。
- 摘要信息需求覆盖率：人工参照的信息需求中，被该层级摘要忠实表达的比例；同时报告无依据新增、条件/否定丢失。完整清单与摘要分开验收。

以知识点和讲解事件区间作为教师阅读单位，时间窗用于观察局部分布；截图的5分钟窗与30%规则作为待验证对照，不直接认定为教学质量标准。具体窗口与阈值通过试点比较确定，不由当前技术实现预先固定。小分母不显示强趋势判断；最低可解释支持量应经试点和专家确定，在冻结测试前登记。不得任意填“80 分为优秀”。

## 5. 报告结论生成规则

每条结论按“观察—候选解释—建议—验证”分开存储。观察由弹幕和媒体引用支持；解释必须保留竞争解释；建议是供教师选择的行动，不是已证实治疗方案。

示例：观察“07:00–09:00 有若干条追问约分条件的反馈”；解释“可能需要补充适用条件，也可能是前置知识不足”；建议“教师回看条件说明，必要时补一个 x=0 的反例”；验证“用与该条件对应的诊断题检查”。如果没有测验，报告只记录行动，不写“掌握率提高”。

没有校准实验前，显示“证据直接/归属待核/模型推测”，不显示 97% 等自报可信度。建议优先序由问题具体性、证据明确度、频度和教师判断解释，不把未经验证的加权公式当科学量表。罕见但严重的概念纠错不能被频率淹没。

## 6. 标注流程

在不同视频、区间、表达类别抽样试标；两名标注者独立阅读规范和同一上下文，先不看模型答案。记录分歧，修订定义，再由导师/领域人员仲裁并冻结版本。测试集冻结后不用于改提示词。正式训练数据可以 AI 预标后人工修订，但独立测试金标准不能由同一模型自评代替。

每轴报告一致性和混淆分布；允许“不明确”，不要以删除难例换高一致率。数学正确性、情绪表达、知识点归属分别判断，避免一个人的领域判断无意变成所有轴的真值。

一致性系数按单位和类别结构选取，说明原始一致率、类别基率及适用假设；多标签可逐类二元评价，问题拆分另评片段/信息需求一致性。不要只给一个系数或照搬合格线。除分层抽样外，选完整连续片段在过滤前逐条复核，覆盖被模型排为无关、纯情绪、非问题的记录。难例加抽结果与代表性样本结果分开，不直接合并声称总体准确率。

## 用户确认：困惑、情绪与问题的处理

用户要求保留所有表示困惑的问题，区分纯情绪宣泄与提问，并为所有提出的问题生成概述和词云。以下规则优先于前文尚待讨论的提问边界。

### 分开判断两件事

一是是否提出可辨识的问题或信息需求；二是是否表达困惑、挫败等情绪或理解困难。二者可以同时成立，不能二选一。

- 只有情绪表达：如“啊啊啊要崩溃了”，没有可辨识的信息需求。保留在情感/困惑相关表达中，不虚构具体问题。
- 笼统理解求助：如“完全没懂，求再讲一遍”。保留为未具体化的理解问题/求助，并标记需结合上下文定位；不能当作纯宣泄丢弃。
- 具体提问：如“为什么这里可以约掉x？”进入问题库，即使没有“不懂”二字。可标为理解性提问，不额外断言真实心理状态；“还能用另一种方法吗”等拓展问题保留不同的问题类型。
- 情绪加提问：如“太难了，为什么这里可以约掉x？”同时保留情绪/困惑与具体问题，不被情绪标签遮盖。
- 隐含问题：如“不知道这里为什么换元”“这两个条件看起来矛盾”。即使没有问号，也保留其中可辨识的信息需求。
- 反问或修辞：如“这不就是定义吗？”保留原文与疑问候选，结合讲解和相邻反馈判断，不能只靠问号归类；不明确的进入待核池，不静默删除。

所有表达困惑的真实问题进入问题库。课程相关的其他问题也进入问题库，但不全部强制归成理解困惑。同时含“不懂/跟不上”的情绪表达还应保留理解状态自述。不得从视频猜一个具体问题，冒充弹幕提出的问题。

### 全量问题概述

每条问题记录保存原文、证据片段、播放时间、知识点候选、问题类型、情绪标签和明确度。把同义问题聚合为问题簇，保留所有原始记录的映射；同主题但所求信息不同的问题不能强行合并。

执行单位为question_unit：如“为什么能约掉x，x=0又怎么办”拆为两项信息需求，每项链接同一原文。弹幕→问题单元→问题簇→知识点候选→报告引用保持可逆查询。每一步记录进入、保留、待核、无法归属和排除原因；同义归并减少的是簇数，不应减少可追溯单元数。

报告包括：全课问题概述 → 按知识点组织的问题清单 → 单个问题的摘要、频次及单条依据。高频问题优先展示但不是准入门槛；只出现一次的问题仍可查询。笼统求助、待核反问与无法归属的问题分别列出，不能在汇总时漏掉。

全量可追溯不等于在一段摘要里逐条复述。摘要可以分层压缩，但完整问题清单必须覆盖已识别提问。统计原始提问条数、归并问题簇数、未具体化求助数、待核数；多标签交叉时明确去重规则。

“所有问题”是保留目标，不能直接作为已达到的模型性能表述。识别召回和后续保留完整性分别报告；笼统/低频/无问号问题进入与否必须在独立材料上检查。MOOC-Rec（E25）的完整语境/非笼统筛选规则不在本项目采用，避免通过清洗删掉最需要教师回应的求助。

### 问题词云

词云只从问题/信息需求及其归并主题提取短语，纯情绪宣泄不进入问题词云。保留否定、条件和学科术语，如“为何不能约分”“x=0的条件”“换元依据”，不能把“不懂”切成“懂”。

默认以包含该主题的不同问题弹幕数作为频次，同条对同主题只计一次；词云旁附精确频次列表。词云显示主要主题，全部低频主题通过完整列表可访问。点击短语 → 对应问题簇 → 单条依据，不制造人数统计。

自动概述标题和词云短语属于规范化表达，不冒充原话。音视频帮助解释省略指代与知识点归属；无法确定时保留“未具体化”或多个候选，不补写不存在的问题。其他积极反馈词云可另设，不能混入问题词云而失去含义。

## 教学方面与发现级判定
