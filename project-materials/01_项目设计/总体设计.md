# 总体设计 ：面向教师改进的弹幕驱动多模态教学反馈解析系统

当前有效设计。失效历史结果已删除，用户原始材料保留。

实施顺序以[分阶段开发与成果计划](分阶段开发与成果计划.md)为准。前期复用已有研究完成基本系统；中期完成三课约三万条弹幕标注，再检验阅读预算约束下的问题覆盖、条件保护聚合与歧义触发局部取证等候选方法，详见[核心创新与验证方案](核心创新与验证方案.md)。以下产品范围与数据契约继续适用；分类、词云、微调及Agent名称不单独作为创新。

工程闭环详见[开放模型研究](../06_工程闭环/开放模型与工程闭环研究.md)、[八环节说明](../06_工程闭环/环节说明/00_阅读导航.md)及[总图](研究与工程总图.md)。已确认可租云GPU；FrameScope仓库已提供并核验来源，当前采用思路借鉴和转写格式兼容。模型主选为待实测的Qwen3.8-27B组合专用ASR/OCR/检索，不把技术选型当作部署结果。B站数据须按当前[取得方案](../02_合规与授权/B站三视频研究数据路线.md)落实。

## 1. 问题和使用者

教师面对大量零散、异步、含玩笑与省略指代的录播弹幕，很难迅速知道：哪里反复被问、表达了什么困难、哪些讲解受到肯定、应该优先回看什么。系统把弹幕自然语言处理（NLP，即由程序识别文本表达的对象、意图与含义）作为主线，利用讲解转录和相关画面帮助解释，再交由教师确认和改进。

建议申报名称：**面向录播网课的弹幕驱动多模态教学反馈解析与教师复盘系统**。Bilibili 是拟验证场景；“多模态”指联合利用文本、声音与画面，不表示三种来源等权打分。音视频辅助是否有效需要对照实验验证。

主要使用者是教师/课程创作者；研究者负责数据与模型审计。学生选课、课程排行榜、课程整体质量等级不纳入本期验收。系统不是学习成效测验，也不用于教师人事评价。

## 2. 产品承诺与边界

| 用户想知道 | 当前可交付表述 | 不成立的替代说法 |
|---|---|---|
| 学生情感变化 | 已收集弹幕中情感表达沿视频播放位置的分布；保留中性、不明确、反讽待核实 | 全体学生真实心理变化、同一批学生的连续情感轨迹 |
| 知识点吸收程度 | 对各知识点的理解自述、困惑、推理解释、方法尝试和纠错主张等线索 | 知识掌握率、学会人数、教学效果因果结论 |
| 高频问题 | 同类问题涉及的弹幕条数、合并规则、时间位置、代表证据 | 提问人数、全班问题发生率 |
| 课堂全面反馈 | 对取得的反馈作多维解析，同时展示缺失与不可判定部分 | 覆盖所有观看者/所有问题 |
| 卡顿、重复 | 源音视频中的停顿、口误候选、内容复述；反馈中的播放异常或重看自述 | 从音视频直接测得网络卡顿率、暂停/回看行为 |

录播弹幕可能跨日期、跨学习背景积累，评论者身份未必是学生；界面默认称“反馈者”或“弹幕表达”。未发弹幕的人没有被观测；无反馈不等于掌握，不把赞美当学会，不把困惑直接当教学失败。暂停与复述可能具有教学作用。

## 3. 研究问题与可否定假设

RQ1：相对只读弹幕，加入局部讲解上下文能否降低指代、否定、玩笑、知识点归属的错误？如果没有稳定改善或增加幻觉，简化模态使用。

RQ2：相对固定时间窗，时间与语义联合归属能否更准确地关联知识点并识别无法归属的反馈？允许多候选和未知，不强制给每条弹幕安放知识点。

RQ3：相对弹幕列表和简单统计图，证据可追溯的报告能否帮助教师在给定时间内发现更多经专家确认的可行动问题，且不过度推断？如果只提高满意度，没有改善任务表现，不宣称教学实效。

RQ4：问题单元拆分与全过程完整性审计，能否在控制误识别的同时减少隐含、笼统、混合情绪及单次问题的漏检与摘要遗漏？分别验证识别召回和已识别问题保留，不把后者等同于发现了全部真实问题。

候选贡献是问题保留与遗漏审计、有证据和拒判机制的局部多模态解析、教师任务验证。CoKnowledge（CHI 2025）已覆盖弹幕分类聚类、视频联动与分层浏览，是核心近邻；弹幕分类、词云和时间轴不单列首创。完整论证和E01–E43来源见03_研究与实验中的《研究依据与设计论证》《权威依据与功能映射》。

## 4. 六个模块及调用链

1. **数据登记与导入**：视频链接用于登记身份及来源；只有存在允许的访问路径才取回数据。优先导入合法取得的弹幕、转录和本地媒体；权限不明用合成材料。校验时长、时间单位、缺片、重复、来源与授权范围。
2. **课程结构辅助**：转录生成带时间的讲解记录；结合课件/板书提出知识点及区间，保留“导入、例题、回顾、过渡”等段落。重复知识点可以对应多个区间。公式与关键条件人工核验，失败时只保留可确认的转录与粗粒度区间。
3. **弹幕多维解析**：拆分同一条文本中的不同评价对象；识别意图、对象、情感表达、理解线索、教学相关性和不确定原因。数学表达、否定词、表情及上下文保留。清洗前后数量可追踪。
4. **知识点归属与问题聚合**：以时间邻域形成候选，结合上下文检索/判别；允许反馈滞后、跨知识点和无法归属。对同义问题聚类，人工可合并/拆分，不把同主题的不同问题混成一条。
5. **证据报告**：由程序计算计数和比例；模型仅基于检索到的证据生成摘要、候选解释和建议，分别保存。报告引用必须能解析到原记录；没有证据不得生成“学生已掌握”等结论。
6. **教师复核与行动**：确认/否定问题、修正归属、记录改进或保留原处理及后续验证办法；记录本次模型输出与人工修订的审计字段。只维护当前报告，不另存历史产物。导出受控摘要与内部证据附录。

调用链：导入包 → 校验与去标识处理 → 转录/章节候选 → 弹幕多轴标签及问题单元 → 归属/聚合与遗漏核查 → 确定性统计 → 引用约束摘要 → 教师复核 → 当前报告。

## 5. 数据契约（设计，尚未实现）

- video：内部编号、来源链接、时长、数据快照日期、内容版本、授权台账编号、取得方式及已知缺失。
- comment：内部编号、播放位置毫秒、去标识文本、清洗状态、重复组、证据片段；默认不存账号、头像、可链接用户哈希。原始敏感信息仅在确有依据和必要时受限处理。
- segment：区间、知识点候选、转录引用、画面引用、识别状态、教师修订。
- annotation：多轴标签、文本依据、候选知识点、待核原因、模型/提示/规范版本；模型自报信心不是经过验证的概率。
- question_unit：一项可辨识信息需求；内部编号、comment_id、原文片段、规范化表达、明确度、问题类型、候选知识点、问题簇、待核状态。一条弹幕可含多个单元，同一原记录不可因聚合而丢失。
- issue：问题簇、支持弹幕编号集合、反例/相反反馈、归属、候选解释、建议、复核状态。
- report：数据说明、统计版本、全部结论引用、缺失项、人工修订和导出范围。

六类首页是多轴标签的检索视图，不是互斥情绪或加总量表。问题弹幕数、问题单元数、问题簇数分别计算。完整问题清单覆盖所有已识别单元；模型漏识别通过过滤前独立抽样审计，不以数据契约假装识别已100%准确。科学复现所需模型与数据标识属于当前审计字段，不产生多份历史设计/报告。

失败要可见：缺弹幕不生成反馈结论；缺音视频则退回文本分析并标记上下文缺失；公式识别冲突转人工；数据稀疏显示“证据不足”；引用失效阻止相关结论进入正式报告。不能静默补齐。

## 6. 基础、分工与范围

FrameScope 文档显示转录、时间戳、截图和报告能力，可候选复用；未验收代码、许可或高数性能。不得在申报中写“已经完成弹幕多模态系统”。具体记录见模块核验文件。

四人建议职责：A 数据治理/后端与复现；B 标注规范/文本基线；C 音视频辅助/对齐；D 前端报告/教师任务实验。两人独立标注时交叉分工，导师或领域专家仲裁。AI 辅助开发、候选标签、文献整理；成员负责读源文、抽查数据、独立测试和解释结果。

先做三条高数视频的流程试点；扩大样本后再讨论跨作者稳定性；计算机作为独立探索测试。高数到计算机不是简单换关键词，需要知识点粒度、术语、问题类别的再核验。先完成核心证据链，词云和大规模推广不占用关键验证资源。

## 8. 教师大纲作为复盘参照

课镜直接完成课程音视频的转写、画面提取与时间定位。教师另行导入教学大纲，系统保留目标、知识点安排、重点难点和教学活动等原文。通过“大纲要求—实际讲解—反馈证据”组织进一步复盘，从而把教师自己的课程意图纳入解释。大纲段落首先作为来源记录，后续经模型及教师确认才能转换为评价对象。

综合评价聚焦内容覆盖、讲解与原定安排的一致性、目标相关的疑问和积极表达，以及可行动的改进建议。报告中的推断应分别引用大纲段落、讲解区间和弹幕，缺少相应材料时保留缺失状态。它不替代学习测验或教学因果评价。当前大纲导入、原文保存和报告展示已实现，语义对应与综合评价继续等待模型接入及验证；页面统一显示【请先连接大模型以获取准确分析】。

立项前工作台已接入Qwen3.5-4B量化权重及视觉投影，配合本地Whisper tiny转写。它承担文本分类、五分钟窗讲解概述、问题概述和大纲—讲解—反馈对应的工程基线。规划中的更大开源模型仍属于待对照方案，不能将其能力写为本机已部署效果。具体模型来源、输入输出和限制见[source/course-feedback/docs/local-model-deployment.md](../source/course-feedback/docs/local-model-deployment.md)，当前整课实测状态以[试验报告](../07_实际试验/BV1Y2DGYoEEw_完整课程试验报告.md)为准。
