# 课镜项目严格评审与研究实施方案

日期：2026年9月15日。审查对象为当前PRD、标注与评价规范、阶段计划和已记录的原型结果。本次是研究设计与文档审查，没有重新运行软件、开展试标或进行全面安全审计。

## 一 评审结论

项目已具备可用的工程起点，但研究设计尚不足以支持“轻量模型优于通用模型”“能评价教学质量”或“已达到国家级成果水平”。主要缺口是独立课程与自然反馈来源尚未落实，任务定义未经过试标检验，主要结局和模型比较尚未收紧。现阶段合理定位为面向教师复盘的反馈解析研究，平台作为材料形成与实验环境。

本轮将主研究问题收敛为：在固定可用材料与报告篇幅下，经过领域标注训练的轻量专用方法，能否以较低推理成本保持或改善学生问题的识别与关键条件保留？讲解定位作为辅助研究，教师复盘任务作为使用价值验证。六类视图、词云、上传播放属于产品功能；大纲关联、跨学科和校园推广按条件递进。

## 二 关键问题与针对性处理

| 严重性 | 原设计问题 | 可能导致的错误结论 | 本轮修正 |
|---|---|---|---|
| 高 | 轻量化、分段、摘要、教学评价和平台同时争取创新 | 每项都做了但无法证明哪项起作用 | 一个主问题、一个辅助问题；其余为产品与拓展 |
| 高 | 数据规模先于课程和参与者落实 | 把积累目标当成可用训练集 | 先落实课程来源与试标耗时，三万条仅远期候选规模 |
| 高 | 只看主动发言且同意分析的学生 | 将有选择的反馈误当全体学生体验 | 全部结论限定于纳入快照的表达，分开报告各处理范围的数量 |
| 高 | API与本地分析纳入不同同意范围 | 数据不同却把结果差异归因于模型 | 主要比较使用获准用于两种处理的同一交集快照 |
| 高 | 模型预标后用相同模型评价 | 循环验证，高估准确性 | 独立人工测试不看模型输出，生成与评分职责分离 |
| 高 | 不同模型使用不同转写、检索和提示 | 系统差异被误写为模型优势 | 组件对照与端到端对照分开，固定预处理基线 |
| 高 | 分歧全部被仲裁为唯一真值 | 主观情绪与歧义被人为抹平 | 区分错误、规范缺陷、合理多解；保留多解与不确定性 |
| 高 | 以API金额对比本地零费用 | 忽略训练、GPU、存储及运维 | 单列推理开销与总拥有成本，报告使用量盈亏边界 |
| 中 | 缺少简单算法基线 | 小模型仅优于不合适的大模型提示 | 加入关键词/线性分类、时间邻近和检索基线 |
| 中 | 教师满意或同意即判断正确 | 使用感受被当作专业正确性 | 学科证据核查与教师可用性分开测 |
| 中 | 多指标多模型择优报告 | 偶然优势被写成稳健结论 | 预先指定主要指标，其他分析标探索性 |
| 中 | 仅写平台功能、未指定软件验收条件 | 已写代码被误报可部署 | 补冻结输入、权限、提示注入、撤回失效与恢复验收 |

## 三 主研究的具体实验

### 3.1 假设与主要指标

主要质量指标为问题单元F1，必要条件保留率为关键约束指标。报告摘要覆盖、六类标签F1、定位、引用支持为次要指标。问题单元一对一匹配由先行冻结的对象、信息需求与条件规则判断，抽样盲评匹配结果；不能仅以字符串相似度决定正确，也不能只由被比较模型自己评分。

主要资源指标为相同批量下实测推理费用与端到端耗时，峰值内存或显存作为部署约束。公开API的服务端资源不可见，所以比较API费用和延迟，不推断它的参数或显存。轻量模型的参数、量化、运行时及硬件如实记录。

探索阶段报告质量—成本曲线及逐课误差。只有在预先确定质量差异界限和统计方案、独立课程数足以支持分析时，才开展正式非劣效检验。差异不显著不等于效果相同；观察到较小样本平均优势也不直接证明泛化。[R1]

### 3.2 两层对照

第一层固定同一转写、画面、候选片段、快照和输出格式，比较反馈处理方法；第二层允许完整系统组合优化，比较实际报告质量与总成本。分别报告两层结果，避免把更好的转写或更宽检索范围归因于小模型训练。

基础对照依次为：关键词与规则或轻量线性分类器；未经专项训练的小模型；经开发集合理调优提示的通用API；专项训练的小模型。聚合另设“直接摘要加完整清单”，定位另设“时间邻近”和“时间加检索”。小模型加API为独立混合方案，报告触发比例、失败比例及实际总费用。

各方法使用相同开发材料和事先记录的调优预算；不故意弱化API提示。保存API模型ID、日期、温度及可获得的版本信息；模型更新导致输出变化时重新记录比较条件。训练允许时至少使用多个随机种子评估波动，具体次数依据资源在正式比较前固定。

### 3.3 数据与同意范围

API与本地比较使用同时获准用于相应接收方、研究评价及本地处理的交集快照；其他记录可用于各自许可范围的产品分析，但不混入主要配对比较。教师提供视频和大纲的处理范围同样核对。不得因为算法比较需要而强迫学生同意外部处理。

按课程及其原片归组，同教师、重复课件或连续系列可能产生相似信息，要记录这些关联。主实验先按课程隔离；如欲声称跨教师泛化，应另保留未见教师材料。预处理参数、词表、阈值、提示示例和训练增强只在训练/开发材料上确定。共享原片的剪辑不得跨集合。[R3]

每次报告列出快照内总记录、可分析记录、交集比较记录、拒判与实际处理数。平台展示总弹幕数不得被误用为分析分母。许可范围不同带来的选择偏差仅描述，不能根据未获准记录的内容补做推断。

## 四 标注修正与专家职责

六类是产品多标签视图，继续保留；主研究重点标注问题识别和条件，不同时把所有标签都承诺为创新成果。笼统困惑、不理解自述、显式求助分别设字段，减少“是否一定属于求助”争议。所有已识别困惑保留可访问记录；只有符合问题定义的记录进入问题指标分母，未形成问题的情绪或自述仍显示在相应视图。

标注分歧分三类：操作或知识错误须纠正；规范不清须修订并重新独立标注；合理语义多解保留标签集合或歧义状态，不为了提高一致率强制统一。教师和学科审核者判断材料是否支持数学解释，不能替学生裁定唯一情绪体验。[R2]

试标应覆盖积极、混合、无关、笼统、低频问题及不确定项。自然抽样与补充难例独立报告。一致性基于仲裁前记录；训练预标可采用模型辅助，独立测试不可依赖同一模型输出形成标准答案。开发团队的交叉审核有助于排错，但不等同于独立学科评价。

## 五 证据报告与教师实验

报告必须保留输入覆盖、统计分母、原文与媒体来源、主张类型及未知状态。建议动作应有可回查依据，不能由弹幕频数直接推出教学缺陷。无测验不论证学习效果，无播放日志不论证实际回看或缓冲。

教师实验与模型指标分开。让教师完成“找出需回应问题并说明证据”和“找出值得保留讲解”等具体任务；原始材料、基础报告、升级报告可用材料一致，界面尽可能一致，仅改变被检验能力。平衡顺序并记录使用时间，防止前一任务记忆影响后一任务。

有效发现先按预先定义的证据规则由独立评分者判断，再评价教师是否采纳。教师满意度作为补充。参与者与任务均带来重复观测，不能把同一教师做十次任务当十名独立教师；样本小时按参与者、课程分别描述并明确探索性质。招募数量由试点变异及可行性决定，不以8—12人自动宣称统计充分。

## 六 工程与可复现要求

自研业务加成熟组件的路线不变。前期只要求授权课程上传播放、自然反馈、API报告、单条引用和复核闭环。MediaCMS不属于必需依赖。基础代码、平台运行、研究结果分开验收。

任务绑定快照ID、媒体摘要、模型与提示配置、处理范围；原文、转写、大纲都按不可信输入处理，材料中的“忽略规则”等文字不得改变系统指令或调用权限。测试伪造证据编号、跨课程引用、重复点击、API超时、进程中断和撤回。撤回先使受影响报告失效，清理规则覆盖导出、缓存与训练副本；已经下载到他人设备的副本无法由系统保证远程回收，应在告知与流程中说明。

训练授权需明确不同于推理授权；商业API输出用于训练或蒸馏前检查条款。开源组件保留许可证与版本摘要，不将第三方能力写为自研算法。本轮设计变更尚未实现所有工程验收项，不据文档更新声称软件通过测试。

## 七 阶段计划与停止条件

前期先落实至少一门真实授权课程和自然反馈，完成API闭环，并提交试标规范、双标分歧报告和数据说明。如果反馈不足，以少量自然数据证明流程可用，暂不启动专用训练。三万条不作为立项前承诺或硬性验收。

中期优先投入问题识别和条件保留：落实独立课程，形成精标集，冻结主要比较，训练并评价轻量方法。其他标签、分段、OCR与大纲只在错误分析证明有收益时扩展。若学习曲线显示新增标注收益低，则优先改进任务定义、证据或界面；若小模型效果未达到要求，保留API方案并报告失败原因。

后期仅在前述评价成立后开展跨教师或计算机课程迁移、校园真实接入及推广。没有独立课程或学科评分者时，不提出强泛化或教学质量结论；没有实际资源记录时，不宣称低成本优势。

三项需导师或团队实际落实的条件：课程及参与者来源；具备学科判断能力的审核者；可投入标注工时及实际算力预算。文档无法替代这些条件。
